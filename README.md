# CropScope — Onion Market Monitor + Satellite Crop Classifier

A Pakistan agriculture dashboard built from published sources, in three tabs. **Onion Market Monitor**: official annual production history, PBS weekly retail prices, and an honest national-forecast audit. **Satellite Crop Classifier**: a genuinely trained AI model — field-level Sentinel-2 time series classifying real Pakistani crop types against Asian Development Bank ground truth, evaluated with a spatial (district-held-out) split, beating a majority-class baseline by a wide margin on macro-F1. **Research & reference appendix**: everything else that is real and reproducible but does not belong in either main story — district yield/trade history, mapped roads, Sentinel-2 scene metadata, a household-use benchmark, two onion AI trials that lost to simple baselines, and a potato satellite-yield demonstration on published Saudi field samples.

## Product scope decision

The dashboard used to put district yield, mapped routes, a satellite scene panel, a household-demand figure, and a potato research lab all on equal footing with production and prices, which overstated how actionable several of them are. The competition domain is agriculture broadly, not Pakistan onions specifically, and the rubric requires an AI step that does real work (classification, prediction, extraction, or agentic decisions) plus a quantified result — not a UI layer over a static number. Reviewed against that bar, three tabs now carry three different, honestly-scoped jobs:

- **Onion Market Monitor** (default tab): exactly two jobs — explore official production history, and track verified weekly city prices — plus one honest AI audit panel showing the trained national ridge model losing to a simple last-season baseline. Nothing here implies a forecast, a dispatch recommendation, or a working yield model.
- **Satellite Crop Classifier**: the project's strongest AI result. A multinomial classifier trained on real Sentinel-2-derived features for 85,618 surveyed Pakistani fields, evaluated on districts the model never saw in training, scoring far above a majority-class baseline on macro-F1 (the metric the dataset's own authors specify, since both seasons are steeply imbalanced). Full methodology and numbers below under "Satellite crop classifier." It covers real Pakistani field crops (wheat, rice, cotton, sugarcane, and others) — no public dataset ties Sentinel-2 imagery to onion-specific field labels, so this is not an onion result, and it is not presented as one.
- **Research & reference appendix**: the potato satellite-yield experiment (the other model in this project that beats a baseline, on 2016 Saudi data, not transferable to Pakistan or onions), plus the onion satellite scene catalog, mapped road reference, trade reference, household-use benchmark, and the two additional onion AI trials — all real, all sourced, none promoted into the main product.

No produce category was added to generalize this further by inventing data. Extending to other crops would need the same thing onion, potato, and the crop classifier each needed: a verified outcome label (yield, price, or crop type) tied to real inputs. The reusable part of this project is the *method* — ingest a named public source, join it to real ground truth, validate with a split that cannot leak (chronological for time series, spatial/district for satellite fields), compare against a naive baseline, and report the result honestly even when the model loses — not an inventory of crops.

## Run

For this computer, open `D:\HACKATHON\dashboard_offline.html` in Edge or Chrome. It contains the generated data and works without a server or localhost access. The data is a snapshot from the most recent pipeline run. Refreshing the browser does not download newer source releases.

To rebuild the snapshot after updating source data, run `python run.py`. This machine has two Python installs — the `python` command (Windows App Execution Alias, 3.13) and a bundled runtime used by `start_dashboard.cmd` (3.12) — and the pipeline now works from either, because `duckdb`, `openpyxl`, and `et_xmlfile` are vendored into `.vendor/` rather than assumed to be globally installed. `numpy` is required separately (already present on this machine in both installs) for the crop classifier; it is not vendored since it is a large compiled package already available natively here. The launcher below starts a local server and also regenerates the offline file, but the in-app browser on this setup may time out when visiting localhost.

`run.py` reads the crop classifier's results from a cache file rather than retraining on every rebuild, since training takes about two minutes. Run `python evaluate_crop_classifier.py` once (or again after changing its method) before `python run.py`; the cache lives at `outputs/crop_classifier_evaluation.json` and `run.py` raises a clear error if it is missing.

In PowerShell, from `D:\HACKATHON`:

**Onion Market Monitor tab:** select a crop season, province, and retail city. Click a production bar or province value to explore directly. The method selector in the audit card compares the trained ridge model with two historical baselines — it is labeled a historical benchmark, not a forecast.

## What the dashboard does not calculate

There is no verified monthly onion arrivals series, buyer order series, current truck quote for these district-market pairs, or available onion-storage capacity with costs and loss rates in the project. Annual output, retail prices, and mapped distances cannot establish a feasible shipment quantity or savings figure. The app therefore does not emit an optimized shipment or storage recommendation. Its price flags are surveyed **city retail-price watch flags**, not district shortage alerts. The previous rule-based district alert and dispatch-readiness card were removed.

The model's average errors are evaluated on chronological holdouts. In the current 14-season backtest, ridge MAE is 195,041 tonnes, last-season MAE is 165,027 tonnes, and three-season-mean MAE is 208,036 tonnes. The national benchmark uses last season because that method has the lowest measured error. This is a real trained AI candidate, but it has **not** demonstrated better forecasting accuracy than a simple baseline.

## Satellite yield feasibility

[Copernicus Sentinel-2](https://dataspace.copernicus.eu/data-collections/copernicus-sentinel-missions/sentinel-2) supplies multispectral surface imagery, and [NASA HLS](https://hls.gsfc.nasa.gov/data-products/) provides harmonized Landsat and Sentinel-2 observations and vegetation indices. [NASA POWER](https://power.larc.nasa.gov/docs/services/api/temporal/daily/) can supply weather covariates. These are real inputs for a future crop-monitoring model.

They are not enough by themselves to predict onion yield. A usable pipeline needs georeferenced onion field or crop masks, planting and harvest dates, and satellite reflectance matched to yield labels by location and season. The project has multi-year yield outcomes for four source districts and recent Sentinel-2 **scene metadata**, but no onion field labels or matched image pixels. Tile cloud-cover percentages describe whole satellite scenes, not onion fields. The dashboard shows those scene records as evidence and does not display an invented vegetation score or yield forecast.

I checked two public Pakistan satellite training sets for a shortcut. The [85,618-field Sentinel-2 dataset](https://zenodo.org/records/22806700) lists wheat, rapeseed mustard, barseem, maize, sugarcane, rice, cotton, sorghum, jantar, and sesame, but no onion. The [Harichand Sentinel-2 ground truth archive](https://zenodo.org/records/6560241) contains garlic, tomato, wheat, and other classes, but its actual class files also have no onion. Neither dataset can validate an onion classifier or yield model. A district-center NDVI value would mix unrelated land uses, so it is not substituted for onion fields.

The first dataset turned out to be a genuine benchmark for a different real task: classifying which field crop a Sentinel-2 time series belongs to. See "Satellite crop classifier" below — it is a real AI result, just not an onion one.

## Potato satellite yield research lab

The lab uses the original [published supplementary workbook](https://plos.figshare.com/articles/dataset/3818955) from the [PLOS ONE potato study](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0162219). It contains measured harvest yield at 135 sample locations, 45 in each of three fields near Wadi Al-Dawasir, Saudi Arabia, in 2016. The input is the **February 11, 2016 Sentinel-2 NDVI** value in the same original row. The paper says yield was measured by harvesting a 3 m² area at each point in April, then scaling to tonnes per hectare. The image date precedes that harvest. The saved workbook is `data/sources/potato_paper/S1_Table.xlsx` (SHA-256 `612C4E3AA654E16D4C8930D7C567A65EB7CADC872F2E6F49F79213D5863B37EA`).

`evaluate_potato_satellite.py` standardizes NDVI using training rows only, fits a one-feature ridge regression with the same penalty (1.0) in every fold, then leaves each entire field out in turn. Each held-out field is predicted by the other two fields' 90 samples. The baseline predicts their mean measured yield. This prevents nearby points in the same field from appearing on both sides of a split. Only the workbook's original “Model” rows are used; its “Validation” sheets contain some derived predictions in vegetation-index columns, so those cells are excluded. The original model rows were eligible for this new field split; the three folds together evaluate 135 points. Feature and penalty alternatives were explored on this small dataset, so this comparison is **exploratory**, not an untouched confirmatory test. It needs independent fields or a later season to confirm the advantage.

| Held-out field | Satellite model MAE | Training-mean MAE | Samples |
| --- | ---: | ---: | ---: |
| 67-S | 6.451 t/ha | 9.618 t/ha | 45 |
| 68-S | 4.999 t/ha | **4.178 t/ha** | 45 |
| 44-S | 6.018 t/ha | 8.000 t/ha | 45 |
| **All fields** | **5.823 t/ha** | 7.266 t/ha | 135 |

This is a real trained satellite model with a modest **exploratory** field-held-out result across these 135 samples, and a negative result in one of three fields. All data are from **one location and one season**. It has no later-year or Pakistan test, cannot produce a current satellite potato forecast, and must not be scaled into national production or used to recommend shipments. It demonstrates a reproducible satellite-yield pipeline, not a validated Pakistan service. Run `evaluate_potato_satellite.py` to regenerate `outputs/potato_satellite_evaluation.json` and `outputs/potato_satellite_points.csv`; the main `run.py` pipeline also embeds those results in the dashboard snapshot.

I also checked a processing tomato Sentinel-2 study, but its farmer-reported field yields are [not publicly released](https://pmc.ncbi.nlm.nih.gov/articles/PMC10007672/), so it cannot support a reproducible tomato module within this build. The public [SICKLE dataset](https://github.com/Depanshu-Sani/SICKLE) has satellite images and yield labels but its yield work focuses on paddy, not a vegetable, and the dataset requires an access form. These were not substituted for missing onion data.

## Satellite crop classifier

This is the project's strongest AI result, and the one built directly to answer the hackathon's requirement for a real data step, an AI step that does actual work, and a number to point to.

**Data.** [Ali, Fraz, Ullah, and Zafar (2026), Zenodo 22806700](https://zenodo.org/records/22806700), CC BY 4.0, the benchmark for the paper "Conformal Crop Classification Across Regions with Sentinel-2 Time Series" ([code](https://github.com/rms-ali247/conformal-crop-sits)). 85,618 fields surveyed by the **Asian Development Bank** across 79 Pakistani districts, two seasons: Rabi 2022 (5 crops: wheat, rapeseed mustard, barseem, maize, sugarcane) and Kharif 2023 (7 crops: rice, cotton, sugarcane, maize, sorghum, jantar, sesame). Each field is a processed Sentinel-2 feature tensor — 7 monthly median composites × 28 channels (10 surface-reflectance bands + 4 vegetation/water indices, each as within-field mean and standard deviation). No raw imagery handling was needed; the published arrays are analysis-ready. The archive was downloaded and its MD5 checksum verified against the one Zenodo publishes (`74f29a0931ccf3834ebc7cde0ef74bcd`) before use. Rabi excludes ~118 off-season rarity fields (Cotton/Sorghum/Jantar/Rice, 1–14 samples each) per the dataset authors' own documented filter, matching their published methodology; Kharif is unfiltered.

**Why this isn't an onion result.** There is no public dataset anywhere that ties Sentinel-2 imagery to onion-specific field boundaries and yield for Pakistan (see "Satellite yield feasibility" above). This dataset has real Pakistani fields and real satellite time series, but its crops are wheat, rice, cotton, sugarcane, and others — not onion. It demonstrates the same AI capability (satellite → trained classifier → validated result) on the best real ground truth that exists publicly for Pakistani field crops.

**Method.** `evaluate_crop_classifier.py` flattens each field's (7, 28) tensor into a 196-feature vector, standardizes using training-fold statistics only, and trains a multinomial (softmax) logistic regression with class-balanced sample weights by momentum gradient descent — plain numpy, no external ML framework, consistent with the rest of this project. The dataset's own documentation is explicit that a random split inflates accuracy, since neighboring fields are spatially correlated: "a crop classifier that scores 0.85 macro-F1 under random cross-validation is not the same classifier once it is pointed at a district nobody surveyed." Evaluation here follows that instruction exactly — districts are shuffled (seed 42) and 20% are held out **entirely**; no district appears in both the training and test sets. The baseline is the single most common crop in the training split, predicted for every test field. Macro-F1, not accuracy, is the headline metric, because both seasons are steeply imbalanced (Wheat is 79% of Rabi, Rice is 55% of Kharif) and the dataset authors flag macro-F1 as the appropriate one.

| Season | Districts train/test | Fields train/test | Model macro-F1 | Baseline macro-F1 | Improvement | Model accuracy | Baseline accuracy |
| --- | --- | --- | ---: | ---: | ---: | ---: | ---: |
| Rabi | 50 / 13 | 19,164 / 7,146 | **0.750** | 0.182 | **4.1×** | 89.8% | 83.2% (always Wheat) |
| Kharif | 58 / 14 | 48,785 / 10,405 | **0.666** | 0.113 | **5.9×** | 87.8% | 65.3% (always Rice) |

Per-crop F1 on the Kharif test districts: Rice 0.95, Cotton 0.89, Sugarcane 0.85, Maize 0.80, Sorghum 0.47, Sesame 0.35, Jantar 0.35 — the model works well on the major crops and is honestly weaker on the rarest ones (support under 250 fields each), which is visible in the dashboard's per-crop table, not hidden.

**What this is and is not.** It is a real, reproducible, spatially-validated multi-class classifier trained on genuine satellite-derived features and genuine government-adjacent survey labels, beating a naive baseline by 4–6× on the metric that matters for an imbalanced problem. It is not an onion model, not a yield predictor, not a current-season forecast (the data is from 2022–2023), and it does not feed into the Onion Market Monitor. Run `python evaluate_crop_classifier.py` to regenerate `outputs/crop_classifier_evaluation.json` (~2 minutes); `run.py` reads that cache rather than retraining on every rebuild.

## Other AI-task trials

`evaluate_additional_ai_tasks.py` checks two more candidate onion-specific AI tasks against simple historical baselines, using the data already in this project and no satellite inputs. Both use the same expanding-window discipline as the national audit: a candidate is only trained on observations that would exist strictly before the held-out one, and both are run with `python evaluate_additional_ai_tasks.py`, writing `outputs/additional_task_trials_summary.csv` plus per-row detail files.

- **District onion-yield trend.** Can a pooled ridge model (district fixed effect, prior-season yield, trailing 3-season mean, time trend) forecast next-season yield (t/ha) better than repeating last season, using the 64-row district history? The 2023–24 rows were independently checked against the MNFSR table; Multan's 2024–25 output has an additional Punjab government check. All four districts share an identical 16-season list (verified in the script before fitting), so a position-index training cutoff is calendar-safe. Across 44 held-out (district, season) pairs: last-season MAE is **1.116 t/ha**, three-season-mean MAE is 1.259 t/ha, and the pooled ridge MAE is **1.286 t/ha** — worse than persistence. Not promoted.
- **Weekly city onion price.** Can the same style of pooled ridge model (city fixed effect, prior-week price, trailing 4-week mean, time trend, with its penalty selected on earlier rolling weeks only) forecast next week's PBS city price better than repeating last week, using all 49 archived weekly releases? Across 29 held-out weeks × 17 cities (493 pairs): last-week persistence MAE is **Rs 10.57/kg**, and the pooled ridge MAE is **Rs 11.55/kg** — worse than persistence. (An earlier trial with a different feature set reached a similar conclusion at roughly Rs 12.32/kg.) Not promoted.

Both results match the pattern already found for national production: with the data actually available at prediction time, naive persistence beats the trained models tried here. The dashboard and this script report that honestly rather than shipping a model that only wins on its own training data.

## Does this meet the hackathon's real-AI requirement?

**Yes, for agriculture broadly: the Satellite Crop Classifier is a real data step, a real AI step, and a number to point to.** It trains a genuine multinomial classifier on real Sentinel-2-derived features for 85,618 Asian Development Bank-surveyed Pakistani fields, validates it on districts the model never saw in training (not a random split, which the dataset's own authors warn inflates scores), and reports macro-F1 of 0.750 (Rabi) and 0.666 (Kharif) against majority-class baselines of 0.182 and 0.113 — a 4–6× improvement on the metric that matters for an imbalanced problem, with accuracy of 87.8–89.8%. This is not a chatbot wrapper over an API: it is feature extraction already embedded in the published data, a trained classifier, and a quantified, reproducible accuracy gain.

**The Onion Market Monitor, honestly, does not have a winning AI model.** The national ridge candidate loses to last-season persistence (195,041 vs 165,027 t MAE, 14 seasons); a district-yield trend model and a weekly-price model, tried the same honest way, also lost to persistence. These are shown in the audit panel, not hidden — the Monitor's value is verified production and price data, not a forecast.

The potato satellite-yield ridge in the appendix (5.823 vs 7.266 t/ha MAE) is a second, smaller real AI result, on 135 Saudi samples — real and reproducible, but on far less data than the crop classifier and with one of its three fields losing to the baseline.

**None of this is an onion-specific satellite result**, because no public dataset ties Sentinel-2 imagery to onion field boundaries and yield for Pakistan — checked directly, documented above, not invented around. What this project delivers that is real and verified across all three tabs: official production, price, trade, and district-yield time series from named public sources with a source URL on every row; a reproducible, leakage-checked evaluation harness (`run.py`, `evaluate_crop_classifier.py`, `evaluate_potato_satellite.py`, `evaluate_additional_ai_tasks.py`) that any reviewer can re-run to get the same numbers reported here; and a UI where measured values, models that lost, and the model that won are never shown as if they were the same kind of claim.
